Gleanvolt s nabíječkou elektromobilu nekomunikuje sám. Dělá to **plugin**: malý program pro značku vaší
nabíječky, který běží vedle Gleanvoltu. Plugin komunikuje s nabíječkou a Gleanvolt říká pluginu, co má
dělat. Plugin má vlastní stránku, kde zadáte adresu nabíječky.

Nabíječku nenastavujete v průvodci. Plugin spusťte, kdy chcete, během nastavení nebo o měsíce později. Než
se připojí, Gleanvolt ukazuje výkon slunce a domácí baterii, ale žádný režim nabíjení nelze spustit
a Přehled odkazuje sem:

![Přehled, než se připojí plugin nabíječky: hlavní věta říká, že žádný plugin nabíječky není připojený, a pod ní je odkaz „How to add your charger“.](../../../../assets/screenshots/overview-no-charger.png)

## Který plugin

| Vaše nabíječka | Plugin | Jeho stránka |
|---|---|---|
| SolaX X1/X3-HAC, X1/X3-EVC | `solax` | port 8098 |
| Huawei SCharger-7KS-S0, SCharger-22KT-S0 | `huawei` | port 8099 |
| go-e Charger (Gemini, HOMEfix, HOME+; hardware V3 nebo novější) | `goe` | port 8100 |
| Shelly TopAC Portable EV Charger | `shelly` | port 8097 |

Jiná nabíječka zatím plugin nemá. Poznámky ke každému pluginu, například co v nabíječce nejdřív zapnout,
najdete v [gleanvolt-chargers](https://github.com/mpospisil/gleanvolt-chargers). Viz také
[Příprava zařízení](../../installation/preparing-devices/). Spusťte jen jeden plugin nabíječky.

## Spuštění pluginu

Spusťte ho stejným způsobem, jakým jste nainstalovali Gleanvolt. Níže `solax` zastupuje název vašeho
pluginu z tabulky: dosaďte svůj, a `Solax` v názvu souboru se změní na `Huawei`, `GoE` nebo `Shelly`.

<Tabs syncKey="install">
<TabItem label="Docker">

Vytvořte složku pluginu a spusťte ho vedle Gleanvoltu:

```bash
sudo mkdir -p /opt/gleanvolt/plugins/solax
sudo chown 1654:1654 /opt/gleanvolt/plugins/solax
sudo chmod 700 /opt/gleanvolt/plugins/solax

docker run -d --name gleanvolt-plugin-solax --restart unless-stopped --init \
  --network host \
  -v /opt/gleanvolt/plugins/solax:/data \
  ghcr.io/mpospisil/gleanvolt-plugin-solax:latest
```

Složka uchovává adresu nabíječky a token pluginu. Pokud Gleanvolt neběží na portu 8090, přidejte
`-e Gleanvolt__Endpoint=http://localhost:<jeho port>`.

</TabItem>
<TabItem label="NAS">

Soubor, který jste vložili podle stránky [NAS](../../installation/nas/), už obsahuje všechny pluginy
nabíječek, vypnuté. V aplikaci pro kontejnery na NAS upravte soubor projektu:

1. Najděte službu `gleanvolt-plugin-solax` a smažte její řádek `profiles: ["solax"]`.
2. Uložte a projekt spusťte znovu.

</TabItem>
<TabItem label="Windows">

<Steps>

1. Z [vydání gleanvolt-chargers](https://github.com/mpospisil/gleanvolt-chargers/releases) stáhněte
   `gleanvolt-plugin-solax-<verze>-win-x64.zip` a rozbalte ho.

2. V novém terminálu přejděte do rozbalené složky a spusťte ho:

   ```powershell
   .\Gleanvolt.Plugin.Solax.exe
   ```

</Steps>

Stejně jako Gleanvolt se zastaví, když zavřete jeho okno, takže ho po restartu Windows spusťte znovu.
Nastavení si ukládá do složky `data` vedle sebe. Jeho stránka se otevře jen v prohlížeči na tomto počítači.
Chcete-li ji otevírat i z telefonu, přidejte `--Urls=http://0.0.0.0:8098` (port vašeho pluginu) a povolte
ho ve firewallu pro soukromé sítě.

</TabItem>
<TabItem label="Linux">

S balíčkem `.deb` je nejjednodušší Docker: viz záložku **Docker**. Nebo z
[vydání gleanvolt-chargers](https://github.com/mpospisil/gleanvolt-chargers/releases) stáhněte
`gleanvolt-plugin-solax-<verze>-linux-arm64.zip` (na PC `linux-x64`), rozbalte ho a v jeho složce spusťte:

```bash
./Gleanvolt.Plugin.Solax --Urls=http://0.0.0.0:8098
```

Použijte port svého pluginu z tabulky.

</TabItem>
</Tabs>

Plugin nepotřebuje token ani adresu Gleanvoltu: najde Gleanvolt na tomto počítači nebo v domácí síti
a požádá o vpuštění. Nezáleží na tom, co se spustí dřív.

:::note[Raspberry Pi s nasazovacími skripty]
Přidejte plugin do `GLEANVOLT_PLUGINS` v `/opt/gleanvolt/.env` (`GLEANVOLT_PLUGINS=solax`) a nasaďte.
`EV_CHARGER_HOST` tam je adresa nabíječky, dokud neuložíte jinou na stránce pluginu.
:::

## Přijetí a nastavení

<Steps>

1. **Přijměte plugin.** Dokud čeká, říká to pruh nahoře na každé stránce. V **Nastavení → Pluginy** nebo
   v kroku průvodce **Dokončení** ho najdete v seznamu **Pluginy žádající o připojení**: klikněte na
   **Přijmout**. Plugin na jiném počítači ukáže kód, který je potřeba nejdřív zkontrolovat: viz
   [Přijetí pluginu](../plugins/#přijetí-pluginu).

2. **Zadejte adresu nabíječky.** Sekce **Nabíječka** v **Nastavení** teď ukazuje připojený plugin a pod
   ním jeho stránku. Zadejte tam adresu nabíječky, nebo ji nechte stránku vyhledat, a uložte. **Otevřít na
   nové kartě** otevře stránku samostatně.

3. **Zkontrolujte to.** Přehled ukazuje stav nabíječky. Režim nabíjení spustíte na stránce **Plán
   nabíjení**.

</Steps>

Pokud Gleanvolt plugin odmítne, sekce **Nabíječka** napíše proč: viz
[Když je plugin nabíječky odmítnut](../charger-refused/).

## Když Gleanvolt nabíječku ztratí

Pokud se plugin zastaví nebo hlásí, že se k nabíječce nedostane, déle než 2 minuty, běžící režim
nabíjení se **přeruší**: Gleanvolt nic neposílá a uvolní blokaci vybíjení baterie. Nabíječka se pak řídí
svým vlastním nastavením. Až bude plugin zpět, režim sám pokračuje. Přehled i **Plán nabíjení** napíšou, co
je špatně, a jejich (i) řekne, kam se podívat. Viz [Plán nabíjení](../../using/charging-plan/).

## Přechod ze zabudovaného ovladače

Do verze 1.3 řídil Gleanvolt nabíječky SolaX, Huawei a go-e sám. Verze 1.4 tyto zabudované ovladače
odstranila: každá nabíječka má teď plugin a Gleanvolt se k nabíječce sám nikdy nepřipojuje.

Spusťte plugin pro svou nabíječku jako výše a přijměte ho. Dokud staré nastavení nabíječky nezmizí, zapíše
Gleanvolt při každém spuštění do logu varování, které plugin jmenuje. Na Raspberry Pi s nasazovacími
skripty spustí plugin nasazení samo, podle `EV_CHARGER_HOST` v `/opt/gleanvolt/.env`, a řekne který; aby
hlášení zmizelo, přidejte ho do `GLEANVOLT_PLUGINS`.
